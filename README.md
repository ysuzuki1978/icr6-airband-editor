# IC-R6 メモリーエディタ

アイコム IC-R6の通常メモリーをMacで編集するアプリです。OPC-478UCで本体を接続し、出張や乗り継ぎに合わせて空港のエアバンドと鉄道無線の受信セットを作れます。初期選択は松山空港（MYJ）と四国（SHK）です。

## ダウンロード

空港と鉄道を一緒に登録できる統合版は、`codex/railway-presets` ブランチから[ビルド](#ビルド)できます。GitHub Releasesで配布中のv1.0.0はエアバンド版です。

[GitHub Releases](https://github.com/ysuzuki1978/icr6-airband-editor/releases/latest) からMac用のZIPを取得し、展開して **IC-R6 メモリーエディタ.app** を開きます。配布ビルドの対象はApple Silicon搭載MacとmacOS 14以降です。動作確認には国内版IC-R6とOPC-478UC（USB ID `0c26:0018`）を使用しました。

配布ビルドはAppleの公証を受けていないため、初回起動時にmacOSが警告を表示する場合があります。自分のMacで使うアプリは下の「ビルド」の手順でも作成できます。 [AppleのMacアプリ起動ガイド](https://support.apple.com/ja-jp/102445)

## IC-R6本体の表示を切り替える

1. 本体の **V/M** を短く押して、**MR** が点灯するメモリーモードにします。
2. **FUNC** を押したまま **BAND（M.N）** を短く数回押し、使いたい表示を選びます。
3. 名前の表示を選んだ場合は、約1秒待つと登録した名前が表示されます。

| 本体の表示モード | 表示例 | 見分けるもの |
| --- | --- | --- |
| `B NAME` | `MYJ`、`SHK` | 空港や鉄道の地域バンク |
| `M NAME` | `MYJTWR`、`MYJYD1` | タワーや車両基地など、バンク内の個々のチャンネル |
| 周波数表示 | `118.350` | 受信周波数（MHz） |
| チャンネル番号表示 | `CH-000` | 通常メモリーのチャンネル番号 |

松山のタワーとATISを名前で見分けたいときは、**M NAME** を選びます。 [アイコムのIC-R6取扱説明書 P36・49](https://www.icom.co.jp/support/manual/2374/)

## 受信セットを作る

1. **受信セット** で **空港のみ**、**鉄道のみ**、**空港＋鉄道** から選びます。両方を選ぶと **空港 · AM** と **鉄道 · FM** を切り替えて周波数を選べます。
2. 最大4空港と最大4鉄道地域から、使う周波数にチェックを入れます。画面下の **登録予定** で件数とバンク名を確認できます。空港を先に、鉄道地域を続けて、Aから順に1か所ずつバンクを割り当てます。たとえば松山空港と四国なら **A · MYJ** と **B · SHK** です。
3. 本体を読み出すかICFファイルを開き、**メモリー一覧に反映…** を押します。続いてメモリー一覧で **本体へ書き込む…** を押すと、通常メモリー全1,300枠を一覧どおりに置き換えます。書き込む前は **受信セットの入れ替えを取り消す** で戻せます。

手入力したチャンネルやバンク未所属のチャンネルも全件入れ替えの対象です。

本体でバンクごとに聞くときは、メモリーモードで **MODE / SCAN** を長押しし、ダイヤルで **MYJ** や **SHK** などのバンク名を選んで **MODE / SCAN** を短く押します。複数のバンクを続けて巡回するときは、本体で対象バンクをリンクして **B-LINK** を使います。 [アイコムのIC-R6取扱説明書 P67–69](https://www.icom.co.jp/support/manual/2374/)

## 国内のエアバンド

空港の周波数を選ぶ画面では、`MYJTWR`（松山タワー）、`MYJATI`（松山ATIS）などのメモリーネームを半角6文字以内で変更できます。バンク名には松山の `MYJ` や中部の `NGO` などの空港コードを使います。

松山でプッシュバックや地上移動の交信を聞くときは、タワー118.350 MHz（`MYJTWR`）を選びます。航空路誌の通信施設表では松山タワーが掲載され、プッシュバックの承認は管制官が行うと記載されています。 [松山空港の航空路誌 AD 2.18・2.20](https://nagodede.github.io/aip/japan/documents/RJOM_full.pdf)

松山を含む83空港・飛行場には **カンパニー（受信候補）** も表示します。各空港の航空会社や日本空港無線サービスとの連絡に使われるVHF AMの候補です。松山の `MYJANA`、羽田の `HNDJAL`、伊丹の `ITMANA` のように、空港コードと会社の略称を組み合わせたメモリーネームを付けています。管制波だけを巡回したいときは、カンパニー欄のチェックを外して入れ替えます。

カンパニー欄の **受信資料 ↗** から空港別の参照先を開けます。公開資料、受信記録、受信機メーカーのプリセットを照合した候補で、現地の最新運用や受信可否は未確認です。 [空港別の周波数資料](https://airband-japan.jimdofree.com/) · [公開の受信記録](https://caiman0223jp.ifdef.jp/airband/freq.html) · [アイコムのプリセットメモリー](https://www.icom.co.jp/support/drivers/4546/) · [日本空港無線サービスのA/G無線](https://www.airportradio.co.jp/service/ag.html)

収録は国内85空港・飛行場です。2026年3月1日表示のAIP Japan公開写しのAD 2.18から、受信用のVHF音声周波数を収録しました。松山には進入図（AD 2.24）に載る岩国アプローチ128.000 MHzも追加しています。緊急用・捜索救難共通周波数（121.500 / 123.100 MHz）とUHFは収録対象外です。各空港の **航空路誌 ↗** から参照したPDFを確認できます。改訂や臨時変更は国土交通省のSWIMで確認できます。 [公開写し](https://nagodede.github.io/aip/japan/) · [国土交通省 SWIM](https://top.swim.mlit.go.jp/swim/)

## 国内の鉄道無線

北海道から九州まで9地域のアナログFMを収録しています。JR各社・JR貨物の列車指令、駅・車両基地・貨物ターミナルの構内連絡、札幌市電・ひたちなか海浜鉄道・京王・富山地方鉄道・名鉄・阪急・近鉄などの受信候補です。私鉄・公営は6地域からの抜粋です。伊予鉄など、周波数とアナログ運用を裏付ける資料が揃っていない事業者は収録対象外です。西鉄の147.800 MHzは福岡県の資料に基づく候補で、現用は未確認です。各行のリンクから出典を開けます。 [JRの公開受信記録（2026年7月12日版）](https://rxlife.net/compilation/jr.php) · [私鉄などの定時通信の受信記録](https://rxlife.net/compilation/scheduled_l1.php) · [札幌市電の受信記録](https://ameblo.jp/dash8rjco/entry-12737753872.html) · [福岡県の西鉄無線局位置図](https://www.bousai.pref.fukuoka.jp/files/uploads/2.pdf)

鉄道の周波数は、地域内で **JR** と **私鉄・公営など** に分けて表示します。本体では **B NAME** で `SHK`（四国）や `TOKAI`（東海）、**M NAME** で `MYJYD1` など各チャンネルの名前を表示できます。

| 松山の受信候補 | 周波数（MHz） | 本体のメモリーネーム |
| --- | ---: | --- |
| 松山運転所 構内連絡 CH1 | 365.1875 | `MYJYD1` |
| 松山駅 信号扱い所 | 365.200 | `MYJSIG` |
| 松山運転所 構内連絡 CH2 | 365.225 | `MYJYD2` |

国内版IC-R6で受信できるモードはFM・WFM・AMです。デジタル方式の列車無線は音声として聞けません。予讃線などに受信記録のある414.425 MHzと414.550 MHzも、国内版IC-R6の受信範囲外です。JRの一部路線で受信記録があるCタイプの415.200 MHzは範囲内です。 [アイコムの製品仕様](https://www.icom.co.jp/lineup/products/IC-R6/) · [鉄道・運輸機構のデジタル列車無線解説](https://www.jrtt.go.jp/construction/technology/telecommunication.html) · [JRの公開受信記録](https://rxlife.net/compilation/jr.php)

通話がない間の連続音でスキャンが止まる場合は、本体の **TRAIN（空線キャンセラー）** を使えます。本体の拡張セットモードで **CANCEL** を開き、対象チャンネルの信号に合わせて **TRAIN1**（単一周波数の連続音）または **TRAIN2**（特定の交互信号）を選びます。 [アイコムのIC-R6取扱説明書 P27–28・53](https://www.icom.co.jp/support/manual/2374/)

## 本体の読み出しと個別編集

1. OPC-478UCをMacとIC-R6のSP端子につなぎ、本体の電源を入れます。
2. アプリの **本体から読み出す** を押します。読み出しには約1〜2分かかります。
3. 一覧でチャンネルをダブルクリックすると、周波数、メモリーネーム、受信モード、ステップ、スキップ、バンクを編集できます。空きチャンネルに登録するときは **追加…** を選びます。
4. **編集を反映** で一覧に反映したあと、必要に応じて **ファイルに保存…** または **本体へ書き込む…** を選びます。書き込みは事前確認、送信、読み戻しの順に進みます。完了まで電源とケーブルをそのままにしてください。

本体のCI-Vボーレートは **AUTO** または **9600** に設定します。メモリーネームは半角6文字までです。周波数を新規入力するときは国内版IC-R6の受信範囲と刻みに合わせてください。 [アイコムのIC-R6取扱説明書](https://www.icom.co.jp/support/manual/2374/)

## バックアップとファイル

- 読み出し時と書き込み直前に、元の全データをICFファイルとして保存します。画面下部の **バックアップ** からFinderで確認できます。
- 受信セットを反映した場合は、通常メモリーとバンク名を一覧どおりに書き込みます。本体から読み出した後に本体側の通常メモリーが変更されていた場合は、送信前に中止します。
- 本体から読み出してチャンネル単位で編集した場合は、変更したチャンネルとバンク名を反映します。同じチャンネルが本体側で変更されている場合は、送信前に中止します。
- ICFファイルを開いて書き込む場合は、そのファイルの通常メモリー全1300チャンネルとバンク名を反映します。空きチャンネルも含まれるので、復元するファイルを確認してから書き込んでください。 [アイコムのIC-R6プリセットメモリー](https://www.icom.co.jp/support/drivers/4546/)

## ビルド

Swift 6とHomebrewを用意してから、次のコマンドを実行します。ビルドしたアプリはプロジェクトのフォルダに作成されます。

```sh
brew install libusb pkgconf
bash build-app.sh
```

アプリはUSB通信用のlibusbを同梱します。ビルドの最低macOSバージョンは使用するlibusbに合わせて設定されます。

`swift test` で編集形式と通信処理を検証できます。通信テストは模擬機器を使います。プリセットの検証も実行する場合は `ICR6_TEST_PRESET` に公式のICFファイルへのパスを指定します。

クローニング通信とデータ配置の参照先です。 [CHIRPのIC-R6対応提案](https://github.com/kk7ds/chirp/pull/1082) · [LinuxのPL2303ドライバー](https://github.com/torvalds/linux/blob/master/drivers/usb/serial/pl2303.c) · [libusbのソース](https://github.com/libusb/libusb/tree/v1.0.30)

配布ビルドには動的ライブラリとしてlibusb 1.0.30（LGPL-2.1-or-later）を同梱しています。ライセンス文はアプリ内の `Contents/Resources/libusb-COPYING.txt` にあり、対応するソースアーカイブは同じリリースから取得できます。
